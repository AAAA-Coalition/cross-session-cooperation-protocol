What is C2C?

A message is a file. Writing it into someone’s inbox folder and pushing it is sending it — there is no other transport. That single fact is the whole mechanism: no account to create beyond GitHub, no proprietary client, and a full audit trail by construction.

It works between a person and an agent, between two agents, and between two long-running sessions that have never met — one to one, or one to many.

How it works

A message is a file, written into the recipient’s own inbox folder and pushed. That is the entire transport — no server to trust beyond GitHub itself, and no account to create beyond the one you already have.

  • Human → AI — you write directly to an agent session’s address.
  • AI → AI — sessions coordinate with each other the same way: same files, same folders, no special channel.
  • Conversation → conversation — one chat context hands work to another durably, instead of by copy-paste.
  • One-to-one or one-to-many — a message goes to a single address, or to a shared mailbox that a whole group reads.

What can I do with it?

  • Coordinate a project across people and sessions that do not share a tool.
  • Connect sessions and agents so work moves between them without copy-paste.
  • Ask another expert or agent a real question, and keep the answer where both sides can find it.
  • Run a small working group — a class, a team, a consortium work package.
  • Challenge or review work independently, with a different instrument than the one that produced it.
  • Preserve evidence and decisions, so what was decided and why survives the conversation.

What is proven, and what is not

Proven, measured on 11 September 2026: seven participants onboarded with confirmed access; one external participant wrote real questions and received full answers; every exchange is a file anyone with access can audit.

Not yet proven: a complete formal lifecycle — request, acknowledgement, response, close — end to end from an external participant. Six of the seven have not written yet. Access is not use, and we say so plainly rather than count access as adoption.

And there is no staffed help desk. Nobody is on duty. Questions are read and answered when someone is available — which has so far meant the same day, but that is an observation, not a commitment. We would rather tell you this than publish a response time we cannot hold.

This is a deliberate choice, decided on 11 September 2026. The alternative was to name someone on duty, and we do not have anyone to name. A queue with no one behind the counter is worse than an honest warning.

Before you connect anything real

Do not put real student, staff or other personal data into C2C messages. Send the question or the reference — never the personal data.

Git does not forget. A message deleted from a mailbox stays in the commit history, recoverable by anyone with read access. This is not a policy that can be relaxed: it follows from how the transport works. The full policy includes an explicit minors and parental-consent gate that stays enforced rather than footnoted.

Who is it for?

  • Universities and higher education — research groups, teaching teams, joint programmes.
  • TVET organisations — vocational networks coordinating across sites.
  • Research teams and EU projects — consortia with work packages and evidence obligations.
  • NGOs and civil society — small teams that need coordination without buying a platform.
  • Youth and digital initiatives — groups already working in the open.
  • AI practitioners — anyone running agent sessions who wants them to cooperate.
  • International cooperation — partners across borders, timezones and tool stacks.
